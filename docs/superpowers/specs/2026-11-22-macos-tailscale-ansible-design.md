# macOS Tailscale Ansible 설계

## 목표

초기화한 Apple Silicon Mac에 오픈소스 Tailscale을 처음 설치하고, 부팅 시 시작되는 시스템 서비스와 Tailscale SSH를 구성한다. 최초 실행의 기준은 Tailscale 앱과 CLI가 모두 설치되지 않은 상태다. Homebrew는 이미 설치되어 있거나 없을 수 있다. `eve`와 `axiom`처럼 설정을 마친 장비에서는 재실행 시 변경이 없어야 한다.

## 접근 방식

사용자가 선택한 1안은 오픈소스 CLI 설치와 서비스 운영을 자동화하고, 기존 GUI에서 처음 전환하는 절차는 운영 가이드로 남기는 방식이다. 검토한 2안은 임시 노드 인증, GUI 연결 전환, 원격 롤백까지 자동화하는 방식이다. 1안은 운영 중인 장비를 먼저 관리할 수 있고, 원격 복구 설치나 인증 자동화가 필요하지 않다.

## 구성

- `ansible/tailscale-macos.yml`과 별도의 macOS 인벤토리 그룹을 추가한다. Linux 및 Raspberry Pi 플레이북은 기존 그룹을 사용한다.
- 최초 실행은 인터넷에 연결된 Mac의 로컬 콘솔에서 한다. Ansible 실행 환경과 필요한 macOS Command Line Tools의 준비 절차를 가이드에 기록한다. macOS가 사용자 확인을 요구하면 해당 단계에서 안내한다.
- Homebrew가 있으면 Homebrew 설치를 건너뛴다. 없으면 공식 설치 절차로 준비한다. `tailscale` 포뮬러는 일반 사용자 권한으로 설치하고, 이후 재실행에서 이미 설치되어 있으면 설치와 업그레이드를 건너뛴다. 서비스 등록과 설정 변경에 관리자 권한을 사용한다.
- Homebrew의 `sh.brew.tailscale` 시스템 서비스를 사용한다. 기존 노드 상태를 읽고 보존한다. CLI는 Homebrew 바이너리와 기본 Unix 소켓을 명시해 확인한다.
- 이미 정상인 서비스는 재시작하지 않는다. Tailscale SSH가 꺼진 경우에는 해당 작업이 현재 접속 경로를 끊을 수 있는지 먼저 확인한다. 원격 장비의 변경은 한 번에 한 대만 한다.
- Tailnet 정책과 태그는 OpenTofu의 관리 범위다. Ansible에서 `opentofu/policy.hujson`, 장비 태그, Aperture 설정을 수정하지 않는다.

## 실행 조건과 중단 기준

| 장비 상태 | 처리 |
|---|---|
| 서비스가 실행 중이며 기존 노드로 로그인되어 있음 | 서비스 등록과 시작 설정, 백엔드, SSH 설정을 점검한다. 정상 상태라면 변경 없이 통과한다. |
| 초기화한 Mac에 Tailscale이 없음 | 로컬 콘솔에서 Homebrew를 확인하고, 없으면 설치한다. Tailscale 포뮬러와 부팅 서비스를 준비한다. Tailnet 인증이 필요하면 중단하고 운영자가 로그인한 뒤 다시 실행한다. |
| 원격 접속이 Tailscale에 의존하고 서비스가 멈췄거나 SSH 전환이 필요함 | 변경 전에 중단하고 콘솔이나 별도 관리 경로를 확보하도록 안내한다. |
| GUI VPN이 연결되어 있거나 기대한 데몬과 다른 백엔드가 응답함 | 전환을 중단하고 수동 가이드를 따른다. GUI 앱이나 기존 Tailnet 등록을 자동으로 제거하지 않는다. |

원격 점검에는 서버 신원을 검증하는 SSH 경로를 사용한다. 실행 전후에 노드 이름과 ID를 비교할 수 있으면 비교하고, 연결 복구를 위해 인증 상태 파일을 교체하거나 SSH 호스트 키 검사를 끄지 않는다. 최초 인증, GUI 제거, 원격 복구는 운영자가 수행한다.

## 검증 기준

1. Ansible 구문 검사와 인벤토리 대상 목록 검사가 통과한다.
2. Tailscale이 없는 초기화 상태에서 Homebrew가 없는 경우와 이미 있는 경우의 분기를 검증한다. 기존 Homebrew는 재설치하지 않고, 두 경우 모두 Tailscale 포뮬러와 부팅 서비스를 준비한다. 검증을 위해 운영 중인 Mac을 초기화하지 않는다.
3. Tailnet 인증 후 Homebrew 서비스, 기본 소켓, Tailscale SSH 상태를 확인한다. 별도 Tailnet 피어에서 새 SSH 연결로 로그인하고, 정상 장비에서 연속 실행 시 두 번째 변경 건수가 0인지 확인한다.
4. `axiom`은 현재 접속 경로를 먼저 확인한 뒤 점검한다. 오프라인이거나 안전한 변경 경로가 없으면 이유를 기록하고 장비 설정을 변경하지 않는다.
5. README와 OKF의 장비 설정 가이드에서 macOS 플레이북의 사용 조건, 수동 전환, 상태 검증을 찾을 수 있다.
